# 목차 정하기

`.work/inventory.md`를 읽고 `book.json`을 씁니다.

이 책은 결정 목록이 아니라 **읽는 사람이 시스템을 따라가며 읽는 이야기**입니다. 읽는 사람은 개발자·기획자·QA·운영자이고, 관련된 결정을 한자리에서 이해하려고 이 책을 폅니다. 결정 원문은 부록에 Layer(L0~L4)별로 따로 실리므로, 본문은 원문의 분류(category, Layer, 폴더)를 따를 필요가 없습니다. 본문은 **읽는 순서**를, 부록은 **찾는 순서**를 맡습니다.

## 부와 장

1. **읽는 사람의 여정을 먼저 정합니다.** 이 시스템을 누가 어떤 순서로 겪는지 한 줄로 적어 봅니다.
   예: "플레이어는 참가 → 경주 → 보상 → 재접속을 겪는다. 운영자는 시즌을 설정하고, QA는 한 경주를 끝까지 검증한다."
2. **부는 관점입니다.** 같은 시스템을 보는 자리마다 한 부를 둡니다.
   예: `플레이어와 함께 달리기`(사용 흐름), `같은 경주를 운영하고 검증하기`(설정·운영·검증). 관점이 하나면 부도 하나입니다.
3. **장은 장면입니다.** 여정 안의 장면이나 질문 하나가 한 장이고, 장 순서는 여정의 순서입니다. 사용 흐름이 없는 저장소(라이브러리, 도구, 문서 규약)라면 "처음 쓰는 사람이 알아야 하는 순서"로 장을 잡습니다.
4. **한 장에는 현행 Atom 5~15건**을 둡니다. 그 장면을 이해하는 데 필요한 결정이 그 장의 `atoms`입니다. 장 안의 순서는 개념(`concept`)과 전제가 먼저, 그다음 장면에서 만나는 순서입니다.
5. **같은 결정이 여러 장에 나와도 됩니다.** 플레이어 장에서 본 규칙을 운영자 장에서 설정값으로 다시 만날 수 있습니다. 다만 두 번째 장에서는 그 관점에서 새로 알게 되는 것만 씁니다.
6. **모든 현행 Atom은 어느 장엔가 나와야 합니다.** 독자가 읽을 내용이 없는 결정(문서 작업 규약, 내부 저장 형식 등)만 `appendixOnly`에 넣어 부록에만 싣습니다. `appendixOnly`가 많아지면 장이 하나 빠진 것입니다. 운영·구현·검증 장을 따로 세울지 먼저 생각합니다.
7. **rnd는 관련 결정과 같은 장**에 둡니다. 시험값만 모은 장을 만들지 않습니다.
8. **컨텍스트 문서**: 방식이 `edit`인 문서(기획서·지침)는 그 내용을 이야기하는 장의 `context`에 넣습니다. 문서가 길면 그 문서만 다루는 장을 둬도 됩니다. `appendix` 문서는 장에 넣지 않습니다. 부록에 원문으로 실리고, 본문에서는 `[[id]]`로 가리킬 수 있습니다.
9. 장의 `layers`에는 그 장의 도입에 쓸 Layer 문서(대개 `part_of`)를 적습니다. L0 비전은 여는 글이 씁니다.
10. 후속 없는 폐기는 따로 둘 곳을 정하지 않아도 부록의 Layer 묶음에 실립니다. 관련 장의 `dropped`에 넣으면 그 장의 근거 목록에도 나옵니다.

## 제목과 장면(lead)

- **장 제목**은 그 장면을 나타내는 짧은 구입니다. 예: "출발선에 서기까지", "결승선에서 열리는 두 가지 보상", "한 시즌의 경주를 설정하는 법". 번호(`1장.`)는 쓰지 않습니다. 도구가 붙입니다.
- **부 제목**은 관점입니다. 예: "플레이어와 함께 달리기". 번호(`1부 ·`)는 도구가 붙입니다.
- **`lead`**는 여는 글의 "읽는 순서" 표에 실리는 한두 문장입니다. 장면 하나와 그 장이 답하는 질문 하나로 씁니다.
  예: "참가 화면을 열고 GO를 누릅니다. 내 점수는 언제부터 쌓일까요?"
  숫자와 식별자는 그 장의 원문에 있는 것만 씁니다(`check`가 봅니다).
- 저장소에 없는 판단("핵심", "완성된", "최고의")을 제목과 lead에 넣지 않습니다.

## 짧은 이름 (labels)

본문 문단 끝의 근거 링크와 부록 차례에 쓰는 이름입니다. Atom의 `title`은 결정 문장 전체라 길기 때문에, 결정이 **다루는 대상**을 짧은 명사구로 붙입니다.

| name | title | label |
| :--- | :--- | :--- |
| `race_score_attainment_tie_v1` | 같은 점수면 먼저 도달한 쪽이 앞선다 | 동점일 때의 순위 |
| `flow_claim_before_next_v1` | 순위 보상을 받아야 다음 라운드를 출발할 수 있다 | 순위 보상 수령 후 다음 출발 |
| `L1_race_system` | L1 레이스 도메인과 이벤트 독립성 | 경기의 규칙과 소유권 |

- 현행 Atom마다 붙이고, Layer 문서와 컨텍스트 문서(`id`로)에도 붙입니다. 제목이 이미 짧은 명사구면 생략해도 됩니다. 그때는 제목을 씁니다.
- 6~16자 안팎. 결론이나 평가를 넣지 않습니다("~는 금지" 대신 "~의 제한").
- Layer 문서의 이름에 `L1` 같은 표기를 넣지 않습니다. 도구가 `L1 · `을 붙입니다.

```

| 항목 | 규칙 |
| :--- | :--- |
| `atomicRoot`, `context[].versions[].path` | `book.json`이 있는 폴더 기준 상대 경로. `/`로 쓴다 |
| `contextIgnored` | 프로젝트 루트 기준 경로 (목록에 보인 그대로) |
| `versions` | 오래된 것부터. 마지막이 현행이고 앞의 것은 부록에서 현행 아래에 놓인다 |
| `id` | 영문 소문자, 숫자, `-`. 한 번 정하면 바꾸지 않는다 (원고 파일 이름이 된다) |
| `atoms` | 현행만. 저장소의 현행 Atom이 책 전체에서 한 번 이상 나오거나 `appendixOnly`에 있어야 한다. 한 장 안에서는 한 번 |
| `appendixOnly` | 본문에 싣지 않고 부록에만 싣는 현행 Atom. 장의 `atoms`와 겹치면 안 된다 |
| `labels` | 이름(Atom·Layer 문서 name, 컨텍스트 id) → 짧은 이름 |
| `lead` | 여는 글의 읽는 순서 표에 실리는 장면·질문 한두 문장 |
| `numbering` | 부·장 제목 앞 번호(`1부 · `, `1장. `). 기본 `true`. 장 번호는 책 전체에서 이어진다 |
| `localNav` | md 쪽 아래의 이전·목차·다음 줄. GitBook에만 쓸 거면 `false` |

책 이름은 프로젝트 README의 제목이나 폴더 이름으로 제안하고 확인받습니다.

  5장. 한 시즌의 경주를 설정하는 법 — … (결정 10건, 앞 장과 겹치는 결정 3건)

```
